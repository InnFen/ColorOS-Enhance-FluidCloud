## 自动迁移流程

1. 保留旧包及其数据，安装并首次打开新版。两个包可以共存，正式包沿用同一发布签名。若配置服务未连接，先在 LSPosed 中识别／启用新版后返回应用。
2. 新版自动检测旧包，需要时请求新版应用的 root 授权。读取旧模块普通设置与启用状态，不需要先升级旧 APK 或自己导出／导入文件。
3. 若旧模块仍启用，新版先保存参数并保持增强未激活，提示在 LSPosed 取消旧包启用、勾选新版及所需作用域。返回新版后会自动复查，确认旧模块停用后完成设置与启用项的保存。
4. 完整重启一次。已经加载到旧进程中的代码，不会因为管理器关掉开关就立即卸载。迁移完成前，新版各进程的激活门保持关闭，避免同时运行两套增强。
5. 确认新版正常后，可在迁移页使用「卸载旧版本」。它会打开系统确认，模块不会静默卸载或清除旧数据。

迁移未完成时，返回手势会退出应用，保留已完成的进度；再次打开会回到迁移页。完成后仍可从管理页的「旧版设置迁移」查看结果。

也可以先在 LSPosed 关闭旧版、启用新版，再首次打开新版完成自动迁移，最后重启。新装且没有旧包时，打开应用完成默认初始化后再重启即可。

## 迁移范围与限制

- 普通配置包括电池、图标、AOD、流体云、SIM 增强开关、安装器选择、系统设置入口、应用深浅外观、玻璃底栏和桌面图标显隐。
- 旧包与新版签名必须匹配。自动读取限定手机主用户及已识别的 LSPosed／Vector 配置结构。未知结构、拒绝 root 或连接异常时停止，不覆盖为默认值冒充成功。
- 成功后不会在每次打开时重新覆盖新版设置。第一次迁移时若新版已有实际配置，先提示覆盖冲突。
- 作用域、LSPosed 启用状态和 root 授权不直接复制或改写，由用户在对应管理器确认。

## SIM PIN

已确认凭据由电话进程管理。本次保留本产品原有的电话端加密存储、Keystore alias、卡片匹配及开机尝试记录；不读取其他独立 SIM 模块的凭据，也不因更换应用 ID 主动清除这些记录。

迁移结果不包含 PIN、完整 ICCID、密钥或暂存凭据，root 辅助程序不读取电话端凭据。对于尚未由电话端确认的暂存 PIN，只检测存在性，不导出解密材料；检测到时新版暂时关闭 SIM 增强并提示重新保存、核对卡槽。请不要把未完成保存误认为已经迁移。

当次开机的尝试记录不会重置，迁移不产生额外一次 PIN 尝试。公开反馈时不要上传 PIN、配置快照或原始迁移输出。

## 读取与失败保护

root 辅助程序从新版自身 APK 加载，仅以只读连接读取旧模块指定分组及启用状态，不直接写入框架数据库，不改变旧模块或其他模块的数据。新版通过自己的框架配置 API 保存设置。

未知配置键不读取其值；序列化记录限制长度和允许的类。迁移结果只含白名单普通参数，保存在新版私有空间用于重试，不生成供分享的导出文件。任务有超时，不增加常驻轮询。

写入时先关闭新版启用项，所有参数确认后再恢复需要的启用项，最后开放进程激活门。失败时尝试恢复之前的新版状态；不能确认恢复时保持激活门关闭。旧包及旧配置不删除，可以修复授权／连接后重试。
